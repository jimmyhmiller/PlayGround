How the machine thinks

Build once.
Repair the diff.

Diffpack is built around one idea: keep a dense module graph alive, then update the smallest truthful part of it.

01
Production build

Source graph in.
Deployable artifacts out.

A production build is a cold, finite pass. Diffpack derives configuration, discovers and transforms the graph, decides what is live, partitions chunks, and writes the finished app.

$ diffpack build ./app --viteclick a phase to inspect

02
Development build

The build becomes
a running system.

Dev starts with a full build too—but does not throw its state away. Bundlers, reachability indexes, render caches, the watcher, and update channels remain alive together.

delivery decision
    Content ≠ source bytesA module is “changed” only when its transformed output hash changes.
    Add edges firstA revision installs replacement paths before removing old ones, avoiding false retractions.
    25% escape hatchIf a detached subtree is ≥ ¼ of the reachable graph, a dense full traversal is cheaper.
